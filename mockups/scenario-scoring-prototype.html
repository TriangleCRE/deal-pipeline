Prototype
This is a discussion mockup, not a shipped feature. It tests Ben's Aug 2026 feedback about splitting property evaluation into a fixed site score and a swappable development-scenario score. It runs on real numbers from a sandboxed duplicate of the 6968 Seminole Trail card (6968-seminole-trail-scenario-sandbox) — the live Seminole Trail card is untouched. Nothing here writes back to the database; the weight slider below only recomputes in your browser.

Site Score + Scenario Score

Worked example for Friday's meeting — built on 6968 Seminole Trail because it's the one deal where we already have two real, fully-modeled scenarios for the exact same parcel.

What Ben asked for

  • Split each property into a site score (acreage, traffic, zoning, access, visibility, demographics — doesn't change based on what we build) and a scenario score (building type, financial assumptions, layout, costs, rents, returns — changes per development idea).
  • Let us run and save multiple scenarios per property, then combine site + scenario scores to find the highest-and-best use — with room to eventually build a goal-seek/optimizer across scenarios.
  • Called out Ruckersville Goodwill/Storage by name: storage on the back land may not pencil once you account for the capital it needs, but a Goodwill-carries-the-debt version could get the deal moving — and today's single blended score doesn't surface that distinction.

The gap the current score hides: at today's default weighting, Storage+Goodwill scores 75.8 and Goodwill-only scores 78.6 — a 2.8-point difference, both landing in "Keep Warm." But the actual dollars aren't close: Storage+Goodwill projects a 0.83× equity multiple and −3.8% levered IRR (≈$1.19M projected loss), while Goodwill-only projects 1.71× and +12.7% IRR (≈$117K profit). A single 1–5 qualitative score compresses a "don't do this deal" scenario and a "this deal works" scenario into a 3-point gap. That compression is exactly what Ben is flagging — the raw financial metrics need to stay visible next to the score, not get folded into it.

What this prototype doesn't do yet

  • Not wired to the live database, the real scoring engine, or the property card UI — it's a static page reading hardcoded numbers pulled from the sandbox duplicate's JSON.
  • Scenarios aren't saved/re-runnable yet — Ben's "save, present, rerun any time" ask needs real scenario storage (new schema + API), not just this page.
  • The weight slider is a toy — a real goal-seek/optimizer would search across many scenarios automatically, not just blend two fixed ones.
  • The heat maps use existing single-axis sensitivity tables from the workbooks — a real version needs a 2D grid (cost × rent) computed live from the financing model, not a lookup of two saved tables.
